06 — وب

وب اپ با React 19، Vite، TanStack Router/Query، Jotai و Radix UI ساخته شده است.

Entry و زیرساخت

فایل وظیفه
src/main.tsx mount اپ و providerها
src/routes/__root.tsx root route، layout کلی و error handling
src/utils/orpc.ts ORPC client و QueryClient
src/index.css Tailwind/theme/global styles
src/routeTree.gen.ts فایل generated توسط TanStack Router

Routeها

Route فایل کاربرد
/ routes/index.tsx صفحه اصلی و لینک قابلیت ها
/login, /register login.tsx, register.tsx auth flow
/chat, /chat/$id chat/* چت و threadها
/image, /image/$id image/* تولید تصویر
/code, /code/$runId code/* دستیار کد
/translation, /translation/$translationId translation/* ترجمه متن و PDF
/summary, /summary/$summaryId summary/* خلاصه سازی
/transcribe transcribe.tsx تبدیل صوت به متن
/settings settings.tsx پروفایل، امنیت، ظاهر، وضعیت app
/admin admin.tsx پنل مدیریت

کامپوننت ها

  • components/ui: primitives با Radix و Tailwind.
  • components/scaffold: shellهای مشترک conversation/tool.
  • components/sidebar: navigation، لیست threadها و feature filtering.
  • components/chat: پیام ها، input، attachment و streaming UI.
  • components/image-generation: فرم تولید تصویر و تنظیمات advanced.
  • components/transcribe, translation, settings, admin: feature-specific UI.

State و data fetching

  • Server state با TanStack Query و ORPC queryOptions/mutationOptions مدیریت می شود.
  • Auth token و user state در atoms/auth.tsنگهداری می شود.
  • مدل انتخابی در atoms/model.tsاست.
  • منطق chat در hooks/use-ai-chat.tsو hooks/use-chat-input.tsاست.

قواعد تغییر UI

  • برای data fetching از ORPC helperهای موجود در src/utils/orpc.tsاستفاده کنید.
  • query invalidation را محدود به query مربوط به همان feature نگه دارید.
  • برای routeهای جدید، pattern routeهای موجود در src/routes را دنبال کنید.
  • متن جدید را در src/lib/textsثبت کنید، نه مستقیم داخل JSX.
  • componentهای shared را داخل components/uiیا scaffoldهای موجود بسازید؛ componentهای feature-specific کنار همان feature بمانند.

ریسک bundle

build وب ممکن است warning مربوط به chunkهای بزرگ بدهد. منبع اصلی react-syntax-highlighterlanguage packها، Mermaid و KaTeX است. این هزینه فعلا برای code rendering و markdown/display featureها قابل قبول است؛ اگر performance مشکل شد، lazy loading یا manual chunking را بررسی کنید.

متن ها و localization

متن های فارسی در src/lib/textsگروه بندی شده اند. برای متن جدید، اول همان فایل feature را به روز کنید و از hardcode مستقیم داخل component پرهیز کنید.

Config و اتصال به API

وب در development از apps/web/vite.config.tsبرای خواندن config.jsonریشه استفاده می کند. WEB_DEV_PORT پورت Vite را تعیین می کند و HOST/PORTآدرس proxy به سرور را می سازند. بنابراین تغییر پورت سرور یا وب باید فقط در همین config واحد انجام شود.

قرارداد خطا و پیام

  • متن خطای قابل مشاهده برای کاربر باید فارسی باشد.
  • raw error backend، exception انگلیسی یا message کتابخانه نباید مستقیم render شود.
  • برای fallback از helperهای error موجود استفاده کنید و متن فارسی کوتاه بدهید.
  • برای toast، alert و empty/error stateها پیام را در src/lib/textsثبت کنید.

چک لیست تغییر frontend

  • route جدید را با TanStack Router بسازید و route tree generated را commit کنید.
  • فرم ها باید loading، success، validation و error state داشته باشند.
  • mutationها بعد از موفقیت queryهای همان feature را invalidate کنند.
  • component بزرگ را فقط وقتی بشکنید که state یا reuse واقعی وجود دارد.
