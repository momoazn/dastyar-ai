Auth و نقش ها

  • JWT در services/auth.tsساخته و validate می شود.
  • protectedProcedureنیاز به user معتبر دارد.
  • adminProcedureعلاوه بر user معتبر، نقش admin را لازم دارد.
  • اولین کاربر ثبت نام شده admin می شود.
  • احراز هویت با header استاندارد Authorization: Bearer <token>انجام می شود.
  • middleware اجباری token را validate می کند و وجود user در دیتابیس را هم چک می کند.
  • middleware اختیاری اگر token وجود داشته باشد آن را validate می کند، اما request بدون token را reject نمی کند.

AI providers

  • ollama-provider.ts: Ollama، OpenAI-compatible و Ollama native endpoints.
  • lmstudio-provider.ts: LM Studio compatible API.
  • ollama-router.ts: انتخاب least-busy Ollama server.
  • stable-diffusion.ts: Stable Diffusion WebUI API.
  • whisper.ts: client سرویس Whisper.

فایل، RAG و پردازش

  • اعتبارسنجی فایل در lib/file-validation.ts.
  • storage سند و تصویر در services/storage.
  • استخراج متن PDF/DOCX/HTML/EML/RTF/XLSX در services/processors.
  • ساخت embedding و chunk retrieval در embeddings.tsو rag.ts.

Config و boot

  • schema و defaults در src/config-schema.tsهستند.
  • loader در src/config.tsفقط config.jsonریشه repo را در dev و config.jsonکنار binary را در release می خواند.
  • generator در src/scripts/config-generator.tsبرای ساخت، نمایش و validate همین فایل استفاده می شود.
  • ترتیب boot: خواندن config، ساخت logger/startup summary، اتصال DB، اجرای migration، ساخت Hono app و listen روی PORT.

قرارداد خطا

خطاهایی که به کاربر می رسند باید فارسی و قابل اقدام باشند. خطاهای داخلی می توانند در log جزئیات انگلیسی داشته باشند، اما پیام ORPC، route response و پیام برگشتی serviceها نباید raw exception یا متن انگلیسی را به وب پاس بدهند.

چک لیست تغییر backend

  • برای procedure جدید، input را با Zod validate کنید.
  • منطق DB را در repository نگه دارید و procedure را نازک نگه دارید.
  • برای operation حساس auth/admin، test کنار فایل مربوط اضافه کنید.
  • بعد از تغییر schema، migration بسازید و docs/config را همسان کنید.
