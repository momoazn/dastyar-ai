# طرح پیشنهادی ساختار پروپوزال (Plan for Master's Thesis Proposal)

این سند ساختار پیشنهادی برای نگارش پروپوزال ۴۰+ صفحه‌ای پروژه «دستیار هوشمند مبتنی بر هوش مصنوعی» (Dastyar AI) را تشریح می‌کند. هدف این است که پروژه به صورت یک «طرح پیشنهادی» (Proposal) ارائه شود، نه یک گزارش کار انجام شده.

---

## عنوان پیشنهادی (Proposed Title)
**طراحی و پیاده‌سازی دستیار هوشمند چندمنظوره آفلاین با تمرکز بر حریم خصوصی و پشتیبانی بهینه از زبان فارسی**
*(Design and Implementation of a Privacy-Preserving, Offline Multipurpose AI Assistant with Optimized Persian Language Support)*

---

## فصل ۱: کلیات تحقیق (Introduction & Generalities)
**تخمین حجم: ۵ تا ۷ صفحه**

این فصل به معرفی کلی موضوع، دلایل انتخاب آن و اهداف پروژه می‌پردازد.

1.  **۱-۱ مقدمه (Introduction):**
    *   معرفی عصر هوش مصنوعی و تغییر تعامل انسان با کامپیوتر.
    *   اشاره به دستیارهای ابری موجود (Siri, Alexa, ChatGPT) و محدودیت‌های آن‌ها.
2.  **۱-۲ بیان مسئله (Problem Statement):**
    *   **وابستگی به اینترنت:** مشکلات تاخیر (Latency) و قطعی اینترنت در برخی مناطق.
    *   **حریم خصوصی (Privacy):** ریسک ارسال داده‌های صوتی و متنی شخصی به سرورهای ابری.
    *   **عدم پشتیبانی مناسب از زبان فارسی:** ضعف مدل‌های بزرگ در درک ظرافت‌های زبان فارسی و گفتار محاوره.
    *   **هزینه:** هزینه‌های بالای اشتراک سرویس‌های API.
3.  **۱-۳ ضرورت و اهمیت تحقیق (Importance & Necessity):**
    *   اهمیت حاکمیت داده (Data Sovereignty).
    *   نیاز به ابزارهای بومی‌سازی شده برای کاربران فارسی‌زبان.
    *   دسترسی‌پذیری (Accessibility) برای افراد با محدودیت‌های دسترسی به اینترنت پرسرعت.
4.  **۱-۴ اهداف تحقیق (Research Objectives):**
    *   **هدف اصلی:** ارائه معماری و پیاده‌سازی یک دستیار هوشمند مدولار و آفلاین.
    *   **اهداف فرعی:**
        *   پیاده‌سازی سیستم تبدیل گفتار به متن (ASR) با دقت بالا برای فارسی.
        *   ادغام مدل‌های زبانی بزرگ (LLM) به صورت محلی.
        *   توسعه سیستم بازیابی اطلاعات (RAG) برای جستجو در اسناد شخصی.
5.  **۱-۵ سوالات تحقیق (Research Questions):**
    *   آیا می‌توان با سخت‌افزارهای مصرفی معمولی، عملکردی نزدیک به سرویس‌های ابری ارائه داد؟
    *   چگونه می‌توان دقت مدل‌های زبانی را برای متون تخصصی فارسی بدون آموزش مجدد (Re-training) افزایش داد؟
6.  **۱-۶ واژگان و اصطلاحات کلیدی (Key Terms):**
    *   تعریف دقیق مفاهیمی مثل LLM, RAG, Quantization, Client-Side Rendering.

## فصل ۲: مبانی نظری و پیشینه تحقیق (Literature Review & Background)
**تخمین حجم: ۱۵ تا ۲۰ صفحه**

این فصل قلبِ افزایش حجم پروپوزال است. در اینجا مفاهیم علمی که **قصد داریم** استفاده کنیم را تشریح می‌کنیم.

1.  **۲-۱ مدل‌های زبانی بزرگ (Large Language Models):**
    *   تاریخچه شبکه‌های عصبی و ترنسفورمرها (Transformers).
    *   بررسی معماری GPT و Llama.
    *   **تکنیک‌های فشرده‌سازی (Quantization):** توضیح علمی اینکه چگونه مدل‌های ۷۰ میلیاردی روی لپ‌تاپ اجرا می‌شوند (GGUF, AWQ).
2.  **۲-۲ پردازش گفتار (Speech Processing):**
    *   تفاوت مدل‌های سنتی (HMM/GMM) با مدل‌های End-to-End.
    *   **معماری Whisper:** بررسی عمیق مقاله OpenAI Whisper و چرایی انتخاب آن برای این طرح.
    *   چالش‌های آوایی زبان فارسی (کسره اضافه، حروف هم‌آوا).
3.  **۲-۳ بازیابی اطلاعات (RAG - Retrieval Augmented Generation):**
    *   مفهوم Vector Embeddings.
    *   پایگاه‌های داده برداری (Vector Databases).
    *   الگوریتم‌های جستجوی شباهت (Cosine Similarity).
4.  **۲-۴ معماری نرم‌افزار مدرن (Modern Software Architecture):**
    *   مقایسه ران‌تایم‌های جاوا اسکریپت: **Node.js در برابر Bun**. (توجیه علمی انتخاب Bun برای پرفورمنس).
    *   معماری **Monorepo**: مزایا در مدیریت پروژه‌های چندبخشی (Server + Web + AI Engine).
5.  **۲-۵ پیشینه تحقیق (Related Works):**
    *   بررسی پروژه‌هایی مثل OpenWebUI، LocalAI و غیره.
    *   **نقد:** چرا این ابزارها برای نیازهای خاص (زبان فارسی + یکپارچگی کامل) کافی نیستند؟

## فصل ۳: روش تحقیق و مراحل اجرا (Methodology)
**تخمین حجم: ۱۰ تا ۱۵ صفحه**

در این فصل توضیح می‌دهیم که **چگونه** قصد داریم سیستم را بسازیم. (زمان افعال: آینده).

1.  **۳-۱ نوع روش تحقیق:**
    *   تحقیق توسعه‌ای-کاربردی (Applied-Developmental).
2.  **۳-۲ ابزارها و تکنولوژی‌های پیشنهادی (Proposed Stack):**
    *   **Back-end:** پیشنهاد استفاده از فریم‌ورک **Hono** بر روی **Bun** به دلیل بنچ‌مارک‌های سرعت بالا.
    *   **Front-end:** پیشنهاد استفاده از **React 19** و **Vite** برای ایجاد رابط کاربری واکنش‌گرا (Responsive).
    *   **AI Engine:** پیشنهاد استفاده از بایندینگ‌های **Go** برای **whisper.cpp** جهت دستیابی به سرعت Native بدون سربار پایتون.
    *   **Database:** استفاده از **SQLite** برای حذف نیاز به نصب سرور دیتابیس جداگانه (User-friendliness).
3.  **۳-۳ معماری پیشنهادی سیستم (Proposed Architecture):**
    *   رسم دیاگرام‌های معماری (Block Diagrams).
    *   طراحی ماژولار: چگونه سرویس‌ها از طریق HTTP/RPC با هم صحبت خواهند کرد.
4.  **۳-۴ روش جمع‌آوری داده و ارزیابی (Evaluation Method):**
    *   چگونه دقت مدل روی زبان فارسی تست خواهد شد؟ (استفاده از دیتاست Common Voice موزیلا برای بنچ‌مارک).
    *   معیارهای اندازه‌گیری: Word Error Rate (WER) برای صدا، Time to First Token (TTFT) برای متن.
