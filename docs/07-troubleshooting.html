08 — عیب یابی

مسیرهای رایج تشخیص مشکل در پروژه.

ترتیب تشخیص سریع

  1. config را validate کنید.
  2. health سرور را مستقیم صدا بزنید.
  3. اگر UI مشکل دارد، Network tab را با route متناظر سرور مقایسه کنید.
  4. اگر AI مشکل دارد، provider محلی مثل Ollama را جدا از اپ تست کنید.
  5. اگر build شکست خورد، اول typecheck و بعد dependency نصب شده را بررسی کنید. 
bun run config:validate
bun run dev:server
curl http://localhost:3000/health

سرور بالا نمی آید

  1. bun run config:validateرا اجرا کنید.
  2. مطمئن شوید JWT_SECRETحداقل ۳۲ کاراکتر است.
  3. پورت PORTآزاد باشد.
  4. DATABASE_FILEقابل نوشتن باشد.

اگر config درست است ولی سرور هنوز بالا نمی آید، مسیر DATABASE_FILEو آزاد بودن پورت PORTرا جداگانه بررسی کنید.

وب به API وصل نمی شود

  • سرور را با bun run dev:serverاجرا کنید.
  • CORS_ORIGINرا بررسی کنید.
  • در dev، web معمولا 5173و server 3000است.
  • /healthباید JSON با status: okبرگرداند.

در development، web معمولا روی 5173و API روی 3000است. اگر صفحه باز می شود ولی داده نمی آید، مسئله اغلب proxy، CORS یا خاموش بودن server است.

مدل های چت دیده نمی شوند

  • OLLAMA_ENABLEDو OLLAMA_BASE_URLرا بررسی کنید.
  • در پنل admin، Ollama serverها را sync کنید.
  • اگر چند سرور Ollama دارید، ollama-router.tsleast-busy server را انتخاب می کند.
  • مدل باید در دیتابیس فعال باشد تا در UI انتخاب شود.

Document upload یا RAG جواب نمی دهد

  • نوع فایل باید در lib/file-validation.tsمجاز باشد.
  • DOCUMENTS_DIRباید قابل نوشتن باشد.
  • برای RAG، embedding model در EMBEDDING_MODELباید در provider موجود باشد.
  • متن از فایل با processorهای services/processorsاستخراج می شود.

تولید تصویر خطا می دهد

  • Stable Diffusion WebUI باید در STABLE_DIFFUSION_BASE_URL فعال باشد.
  • مسیرهای /sdapi/v1/optionsو /sdapi/v1/txt2img باید پاسخ دهند.
  • IMAGES_DIRباید قابل نوشتن باشد.

Whisper کار نمی کند

  • bun run dev:whisperرا اجرا کنید.
  • مدل در apps/whisper/modelsوجود داشته باشد.
  • اگر Go test خطای whisper.hداد، whisper.cpp headers/build artifacts آماده نیستند.
  • /healthسرور Bun وضعیت Whisper را هم برمی گرداند.

برای توسعه chat، settings و admin، آماده نبودن Whisper blocker نیست. فقط transcription را unavailable می کند.

Build وب warning بزرگ بودن chunk دارد

فعلا known issue است. منبع اصلی language packهای syntax highlighter، Mermaid و KaTeX است. اگر لازم شد، با dynamic import یا manualChunks کم شود.

فایل های route بزرگ هستند

چند route وب عمدا هنوز بزرگ مانده اند و در cleanup به عنوان ریسک آینده ثبت شده اند: apps/web/src/routes/code/index.tsx، apps/web/src/routes/code/$runId.tsxو apps/web/src/routes/translation/index.tsx. اگر روی این بخش ها کار می کنید، extraction تدریجی به component/hookهای کوچک تر امن تر از rewrite کامل است.

Archive فایل لازم را ندارد

  • scripts/archive.tsاز git ls-files --cached --others --exclude-standardاستفاده می کند.
  • اگر فایلی ignored باشد وارد archive نمی شود.
  • generated/runtime paths مثل dist، release، آپلودها و مدل ها عمدا حذف می شوند.

تست ها fail می شوند

  • اول همان فایل test را جدا اجرا کنید تا خروجی کوتاه تر شود.
  • خطای server معمولا از config، migration یا mock ناقص می آید.
  • خطای web معمولا از DOM، query cache یا timing async می آید.
  • تست unit نباید به Ollama، Whisper یا Stable Diffusion واقعی وابسته باشد. 
bun test apps/server/src/path/to/file.test.ts
bun --cwd apps/web test src/path/to/file.test.tsx

Whisper Go tests محیطی هستند

تست کامل Go برای Whisper بدون آماده بودن whisper.cpp headers/build artifacts hermetic نیست. اگر خطا مربوط به native dependency بود، اول smoke مسیر runtime را با bun run dev:whisperبررسی کنید.
